🚀 4. New Client Onboarding & Chat-Driven App Creation Flow

How to Onboard a Client & Build a New Application

From initial conversational requirement to live Vercel production deployment in minutes.

💬 Start Chatting with Bot (@meta_ceo_bot)

1. Intake & Requirement Gathering

Client connects directly with Marco Silva (@meta_ceo_bot). The bot conducts an interactive 3-step intake: Core Problem, Target Audience, and Key Functional Metrics.

2. Dedicated Topic & Hermes Pipeline

Hermes provisions a private forum topic in Neoll Labs Tech🚀 and instantiates tracked cards in native Hermes Kanban (kanban.db), assigning specialist developer agents.

3. Justified DB & Cost Optimization

A cloud database (Supabase) is provisioned ONLY when strictly justified by data requirements (auth, sync). Local-first apps use client storage to eliminate unnecessary infrastructure costs.

4. Isolated Worktree & Vercel Staging

Agents build the application in an isolated git worktree with clean semantic URLs (e.g. /tab/dashboard, never /?tab=...) and deploy preview to <app>.staging.neoll-labs.com.

5. Free Tier (1 App & 5M Tokens) & Polar Promotion Gate

Starter Tier: Every client receives 1 Free Application with up to 5,000,000 (5M) tokens included at zero cost. When ready, [ ✅ Approve & Ship to Prod ] promotes the free app immediately. A 2nd app or usage exceeding 5M tokens triggers a frictionless subscription checkout via Polar.sh (€19.90/month) with automated VAT and invoicing. Note: GitHub repositories remain 100% internal and are never shared with clients.

💡 O Padrão de Pedido Recomendado (3-Step Agentic Request)

Para obter execuções autónomas imediatas e de alta precisão em qualquer tópico, estrutura o teu pedido em 3 pontos:

1. O Quê (Feature / Correção)

Especifica o objetivo funcional claro (ex: "Adiciona um filtro de setor no topo da página de eventos").

2. Critério de Aceitação

Como sabemos que está pronto (ex: "Deve guardar o filtro na URL e atualizar a lista sem recarregar").

3. Ação Autónoma

O agente escreve o código, testa o build, faz commit e publica em produção/staging com o link de verificação.
